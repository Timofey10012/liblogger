# liblogger


Библиотека логирования на C++17 с поддержкой записи сообщений в файл и отправки сообщений по TCP-сокету.


Проект выполнен в рамках учебного задания.


## Возможности


Библиотека предоставляет два логгера:


- `FileLogger` — запись сообщений в файл;
- `SocketLogger` — отправка сообщений на TCP-сервер.


Для сообщений поддерживаются три уровня важности:


- `Info`
- `Warning`
- `Error`


Логгер игнорирует сообщения, уровень которых ниже установленного уровня логирования.


Каждая записанная запись содержит время, уровень важности и текст сообщения:

```
[2026-08-21 18:37:33][INFO] Hello World!
```

Библиотека является потокобезопасной: доступ к общим ресурсам защищён с помощью `std::mutex`.

Передача сообщений в логгер выполняется в отдельном рабочем потоке. Основной поток отвечает за ввод пользователя, а рабочий поток получает сообщения из потокобезопасной очереди и передаёт их логгеру.

## Требования


- C++17
- GCC
- CMake
- Linux 


Сторонние библиотеки не используются.


## Сборка

Создать директорию для сборки:

``` 
cmake -S . -B build
```

Собрать проект:

``` 
cmake --build build
```

В результате будут собраны библиотеки, тестовое приложение, сервер статистики и тестовая программа для проверки сервера.

## Запуск приложения

Приложение принимает два аргумента:

``` 
./example_app <log_file> <default_log_level>
```

Например:

``` 
./build/example_app app.log info
```

После запуска приложение запрашивает сообщение:

```
Message: Hello World
Level (info/warning/error, Enter for default):
```

Если уровень не указан, используется уровень по умолчанию, переданный при запуске программы.

Также можно указать уровень непосредственно для сообщения:

```
Message: Something went wrong
Level (info/warning/error, Enter for default): error
```

### Завершение

Приложение обрабатывает сигнал `SIGINT`. Для корректного завершения программы можно нажать `Ctrl+C`.

При завершении приложение дожидается обработки сообщений, находящихся в очереди, и корректно завершает рабочий поток.

## FileLogger

Пример использования:

```
FileLogger logger("app.log", LogLevel::Info);


logger.log(LogLevel::Info, "Application started");
logger.log(LogLevel::Warning, "Something may be wrong");
logger.log(LogLevel::Error, "Something went wrong");
```

Сообщения записываются в указанный файл.

### Изменение уровня логирования

Уровень логирования можно изменить во время работы:

```
FileLogger logger("app.log", LogLevel::Warning);

logger.log(LogLevel::Info, "This message will be ignored");

logger.setLogLevel(LogLevel::Info);

logger.log(LogLevel::Info, "This message will be written");
```

## SocketLogger

SocketLogger подключается к TCP-серверу по указанному IP-адресу и порту:

```
SocketLogger logger("127.0.0.1", 9000, LogLevel::Info);


logger.log(LogLevel::Error, "Connection failed");
```

Для передачи данных используется TCP-соединение.

## Server

Проект также содержит консольное приложение `server` для сбора статистики по сообщениям, получаемым от `SocketLogger` по TCP-соединению.

Сервер принимает параметры:

```
./server <port> <messages_count> <timeout_seconds>
```

Например:

```
./build/server 9000 3 2
```

где:

* `port` — порт, на котором сервер ожидает TCP-соединение;
* `messages_count` — количество сообщений, после которого выводится статистика;
* `timeout_seconds` — интервал ожидания, после которого статистика выводится, если она изменилась с момента последнего вывода.

### Возможности сервера

Сервер:

* принимает сообщения по TCP-соединению;
* выводит каждое принятое сообщение в консоль;
* подсчитывает общее количество сообщений;
* подсчитывает количество сообщений каждого уровня важности;
* подсчитывает количество сообщений, полученных за последний час;
* определяет минимальную длину сообщения;
* определяет максимальную длину сообщения;
* вычисляет среднюю длину сообщения;
* выводит статистику после получения заданного количества сообщений `N`;
* выводит статистику после таймаута `T`, если статистика изменилась.

Для ожидания сообщений и таймаута используется системный вызов `poll()`.

### Формат сообщения

Сервер ожидает сообщения в формате, используемом `SocketLogger`:

```
[2026-08-22 20:07:29][WARNING] Hello World!
```

При обработке сообщения сервер извлекает:

* время отправки;
* уровень важности;
* текст сообщения.

Время сообщения преобразуется в `std::chrono::system_clock::time_point`, что позволяет учитывать сообщения за последний час.

### Буферизация TCP-сообщений

Поскольку TCP не сохраняет границы отдельных сообщений, сервер использует накопительный буфер.

Полученные данные добавляются в буфер до тех пор, пока в нём не обнаружится символ `\n`, обозначающий конец сообщения. После извлечения полного сообщения оставшаяся часть данных сохраняется для дальнейшей обработки.

Это позволяет корректно обрабатывать ситуацию, когда одно TCP-сообщение содержит несколько логов или один лог приходит несколькими частями.

### Архитектура сервера

Логика сервера разделена на несколько компонентов:

* `server.cpp` — создание TCP-сокета, подключение клиента, получение данных и основной цикл обработки;
* `log_parser.cpp/.hpp` — разбор полученных логов;
* `statistics.cpp/.hpp` — подсчёт и вывод статистики.

Для хранения времён сообщений используется `std::deque`. При выводе статистики из него удаляются сообщения, время которых старше одного часа.

## Тестирование сервера

Для проверки взаимодействия с сервером используется отдельная тестовая программа `server_test`.

Тестовая программа принимает параметры:

```
./server_test <port>
```

Она подключается к серверу через TCP и отправляет несколько сообщений разных уровней важности с паузами между ними. Это позволяет проверить:

* установление TCP-соединения;
* получение сообщений сервером;
* обработку нескольких сообщений;
* обработку сообщений разных уровней важности;
* вывод статистики после заданного количества сообщений;
* вывод статистики после таймаута.

Сервер и тестовая программа могут быть запущены в разных терминалах.

Например, сначала:

```
./build/server 9000 3 2
```

а затем:

```
./build/server_test 9000
```

## Тестирование

Для запуска тестов используется CTest.

Сначала собрать проект:

``` 
cmake --build build
```

Затем:

``` 
ctest --test-dir build --output-on-failure
```

### Тесты проверяют основные возможности библиотеки:

- запись сообщения в файл;
- фильтрацию сообщений по уровню важности;
- изменение уровня логирования;
- обработку ошибки открытия файла;
- отправку сообщения через SocketLogger.

## Сборка статической и динамической библиотек

### Проект содержит две цели сборки библиотеки:

- `liblogger_static` — статическая библиотека;
- `liblogger_shared` — динамическая библиотека.

Тестовое приложение в текущей конфигурации использует статическую версию библиотеки.

## Обработка ошибок

Ошибки работы библиотеки приводят к выбросу исключений `std::runtime_error`. Приложение перехватывает исключения и выводит информацию об ошибке в консоль.
